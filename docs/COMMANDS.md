# Native command discovery and syntax

## Commands

- `/shelf`: Telegram inline panel when its native connection and owner policy are available; otherwise a text list. Opening the panel does not save.
- `/shelf <query>` or `/shelf search <query>`: search saved delivery metadata. Use `/shelf search help` or `/shelf search add` to search reserved words.
- `/shelf dl <number>` or `/shelf download <number>`: send that item from your last numbered result/page, valid for ten minutes and scoped to your user/chat/topic/profile/session. No model call.
- `/shelf r3`: send up to three most recently updated attached entries; `r1`–`r5` supported. Missing files count as unavailable, with no replacement or automatic retry.
- `/shelf add [title] [#tags] [--description "text"]`: save one recent file from the invoking conversation without a model or injection permission on Desktop, TUI, CLI, API-server commands and authorized Telegram chats/topics. Several files open a native Telegram chooser with Cancel; other clients point to **Saved → Delivery Shelf → Add** to select a file. Existing registrations keep their metadata. Missing context or files never trigger an agent handoff.
- `/shelf add [title] [#tag1, tag2] --file <root:path> [--description "text"]`: select an exact existing file under an approved root. Quote file references containing spaces. Title/tags precede options.
- `/shelf help`: short browsing/search help, without setup jargon or manual file syntax; does not save.
- `/shelf help advanced`: full manual-save syntax and limitations; works without session metadata or handoff consent.

Ordinary Add defaults to the filename as title and empty tags/description;
it preserves any supplied fields. It recognizes explicit `MEDIA:` references in the
active conversation segment, not compressed/ancestor history or arbitrary links.
See [source limits](DETERMINISTIC_ADD.md). For the advanced `--file` workflow only,
omitted title, tags and description are generated by the current agent.
Supplying all metadata with `--file` saves directly without a model turn. Assisted
saves need current context and the explicit per-plugin injection consent described
in [Operations](OPERATIONS.md#enable-agent-assisted-metadata). Acceptance of a
handoff is not a completed save; the agent must save and verify before confirming.

**Telegram groups/topics:** ordinary Add, browsing and file sending work for configured
Shelf owners without injection permission. Only the advanced `--file` workflow with
missing metadata still needs a private chat or fully supplied metadata. Native
panels/Add require the additional owner policy. See [Telegram setup](TELEGRAM.md).
Numbers work only for acknowledged native lists; the text-only fallback is unnumbered.
An uncertain list delivery disables numeric downloads for that result context;
entry → **Send file**, recent-file shortcuts and Desktop/Dashboard remain available.

## Menu and `/help`: verified host behavior, not a custom menu

The plugin declares `provides_commands: [shelf]` and calls the public
`ctx.register_command` API with a description, optional-leading `args_hint`, and
`argument_mode="text"`. It does not publish Bot API menus, register a duplicate
command, override `/help`, patch host code, or enable itself.

The canonical Telegram menu uses the native plugin registry. Its plugin descriptions
are capped at **40 characters**. The entry is deliberately short and untruncated:
**Browse/add deliveries; /shelf help**. Selecting it sends bare `/shelf`, not its
argument hint. Hints beginning with `<` are excluded by the host's Telegram menu;
this command starts with `[` because bare invocation is supported.

**Official Hermes v0.22.5 limitation:** native gateway `/help` and `/commands`
render built-ins and skills, but omit registered plugin commands entirely—not
just their argument hints. Registration cannot make `/shelf` appear there on that
host. Use `/shelf help` for syntax. This remains an upstream host gap; we do not
claim the global `/help` requirement is met or substitute a plugin-owned help menu.

## Operator setup (never applied by the plugin)

1. Install and enable the backend plugin in the profile used by the intended
   Telegram gateway; a Desktop-only installation does not register gateway commands.
   Follow the normal install instructions and verify `hermes plugins list` in that
   profile. A resident process must load the new registration; changing files or
   generating a menu in a separate process does not update it.
2. Merge menu priorities into that profile's configuration using supported Hermes
   configuration editing, preserving existing entries. Example for Shelf alone:

   ```yaml
   platforms:
     telegram:
       extra:
         command_menu:
           max_commands: 60
           priority_mode: prepend
           priority: [help, new, stop, shelf]
   ```

   If Conversation Bookmarks is independently installed, add `bookmark` to the
   priority list too. This is an ordering, not an allowlist. Preserve important
   safety commands and existing priorities; sufficient room must remain before
   the cap. `append` does not promote plugins ahead of the host's built-in priorities.
   Default cap: 60; supported configured bounds: 1–100. On the pinned v0.22.5
   fixture, built-ins alone displace Shelf at the default cap. Registration does
   **not** guarantee menu visibility without priority configuration.
3. Let the authorized gateway load the plugin and perform its normal menu
   registration; authorize a restart only when needed for resident code/native
   handlers. `/reload-skills` is not a plugin reload. Native force rediscovery
   disposes old command registrations, and targeted unload removes them, but neither
   is evidence that a remote Telegram menu has been republished. Disabling config
   alone leaves a resident command until the host reconciles/reloads it.
4. The host registers default, all-private-chat and all-group-chat scopes after
   connection. Forum menus are registered lazily for the **parent chat**, not each
   topic. More-specific chat or language scopes may override broader menus.
   Host menu fingerprints include language and payload; changed fingerprints clear
   the host's cached forum registrations for lazy refresh. Telegram's client cache
   is separate. An authorized operator should verify the intended bot identity and
   read back the actual applicable scope/language before blaming client caching.
   Do not assume a fresh locally generated list proves a live published menu or
   working dispatch. The plugin never reads credentials or refreshes scopes itself.

## Reproduce offline

`tests/native_command_discovery.py` is part of `scripts/verify.sh`. Select a
read-only official host checkout with `HERMES_SOURCE`; all runtime homes/configs
are disposable fixtures. No bot, model, gateway startup or production state is used.

```sh
HERMES_SOURCE=/path/to/hermes-agent python tests/native_command_discovery.py
# Optional coexistence probe; the companion is not a dependency:
HERMES_SOURCE=/path/to/hermes-agent python tests/native_command_discovery.py \
  --companion /path/to/hermes-conversation-bookmarks
```

The probe exercises actual PluginManager discovery, registry metadata, the canonical
menu with default/capped/prepend/append configurations, the native gateway `/help`
handler and `/commands` renderer, plugin syntax dispatch, force reload, targeted
unload and config-disable reconciliation. It records the host revision and plugin
source hashes, and asserts no catalog database was written. The v0.22.5 help gap
is explicitly asserted so a future upstream fix requires revisiting these docs.
Live bot publication, scope readback and actual inbound commands still require
separately authorized acceptance tests.
